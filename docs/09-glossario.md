## Termos do projeto

| Termo | Definição |
|---|---|
| **RF** | Requisito funcional. O que o sistema faz. |
| **RNF** | Requisito não funcional. Como o sistema faz — desempenho, acessibilidade, compatibilidade. |
| **RN** | Regra de negócio. Restrição do domínio, válida independente da tecnologia. |
| **US** | User story. Necessidade descrita do ponto de vista de quem usa. |
| **Critério de aceite** | Condição objetiva que define se uma história está pronta. Formato Dado/Quando/Então. |
| **MoSCoW** | Método de priorização: Must, Should, Could, Won't. |
| **Backlog** | Lista priorizada do que falta fazer. |
| **Sprint** | Período fixo de trabalho com uma meta definida. |
| **ADR** | Architecture Decision Record. Registro curto de uma decisão técnica e do porquê dela. |
| **Definição de pronto** | Checklist que toda história precisa cumprir para contar como entregue. |

## Termos técnicos

| Termo | Definição |
|---|---|
| **HTML semântico** | Uso de elementos que descrevem o significado do conteúdo (`header`, `main`, `article`) em vez de `div` genérica. Melhora acessibilidade e SEO. |
| **Responsivo** | Layout que se adapta ao tamanho da tela sem quebrar nem exigir rolagem horizontal. |
| **Mobile first** | Escrever o CSS primeiro para telas pequenas e ampliar com `@media (min-width)`. |
| **`localStorage`** | Armazenamento do navegador, por origem, que persiste depois de fechar a aba. Guarda texto; objetos vão como JSON. |
| **DOM** | Representação da página em objetos, que o JavaScript manipula. |
| **Event listener** | Função registrada para rodar quando algo acontece na página (clique, envio de formulário). |
| **Contraste 4.5:1** | Razão mínima de contraste entre texto e fundo exigida pela WCAG nível AA para texto normal. |
| **WCAG** | Web Content Accessibility Guidelines. Diretrizes de acessibilidade para a web. |
